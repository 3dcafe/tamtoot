# Tamtoot 0.1.8: more reliable SSH sign-in

**Release notes in progress · 19 October 2026 · version 0.1.8+8**

[Русская версия](0.1.8.ru.md) · [Project overview](../../README.md)

## Local coding agent loop protection

Action arguments and file versions now participate in repetition checks. Third reads of unchanged files are blocked and unavailable tools are removed from the JSON Schema. Failed replacements receive a small current excerpt and one exact retry. Placeholder paths and unrequested new files are rejected. Edited regions must be read before finishing. Action and no-progress budgets bound runs.

Reasoning-only replies from the Ollama compatibility API trigger a native `/api/chat` recovery with `think: false` and at most 800 tokens. Models rejecting `think` get one retry without it; another empty reply stops the run with diagnostics.

## Ignore local IDE data

Opening primary or additional workspace folders now creates or extends `.gitignore` for Tamtoot caches, agent state, worktrees and local settings, including nested projects. Existing rules are preserved. Shared HTTP requests and `environment.json` remain available to Git. Already tracked files are not removed from the index.

## Agent recovery after missing files

Missing reads now return an actionable tool result with current project paths. Missing paths are excluded from subsequent read schemas until created. The local prompt also clarifies that C# class libraries do not require `Program.cs`.

## Multiple workspace folders

**Open folders…** lets you select multiple directories on Windows, macOS and Linux. The explorer and agent use them as one workspace. The first folder is the primary root; the others are additional roots. The folder list is restored between sessions.

## Fix connections closing immediately after SSH authentication

Fixed a race when an SSH server sends a connection-level request immediately
following USERAUTH_SUCCESS, such as OpenSSH's host-key advertisement. The client
previously could process that request while still marked as authenticating,
reject it and close the connection. Authentication state is now committed when
the success packet arrives, before subsequent messages are processed.

Server host-key verification and the existing encryption requirements remain in
place. This fix does not add support for new authentication methods or algorithms.

## Clearer disconnection errors

When the underlying transport closes with a recorded error, the active SSH
operation receives that reason instead of only a generic connection-closed
message. This helps distinguish transport failures from rejected credentials.

## Validation

- Added regression coverage for immediate OpenSSH host-key advertisements after
  authentication success and propagation of transport errors to active commands.
- Added an opt-in LAN handshake test. It uses temporary, in-memory host trust,
  requests advertised authentication methods, and sends no passwords, private
  keys, shell requests or remote commands. It is skipped by default.
- A LAN OpenSSH 10 server was checked through encrypted key exchange and the
  authentication-service response. Full sign-in and interactive shell validation
  still require the user's credentials and an application check.

To run the optional diagnostic against your own server:

```sh
TAMTOOT_SSH_DIAGNOSTIC_HOST=192.0.2.1 TAMTOOT_SSH_DIAGNOSTIC_USER=example flutter test --no-pub test/ssh_lan_diagnostic_test.dart
```

These notes describe the current source changes, not a published store build.

Validation result: static analysis passed. The full suite recorded 460 passes,
2 skips and one PTY `top` initialization timeout. That test passed when rerun
separately; the initial full run was not clean.

## Password entry and sign-in diagnostics

If the saved password cannot be read from secure storage, the connection now
falls back to manual password entry without deleting the saved credential.
Unexpected sign-in failures identify the authentication stage and exception
type; raw provider exception text is excluded to avoid exposing credentials.
Added coverage for unavailable secure storage and safe failure diagnostics.

## Saved-password buffer ownership

Fixed `UnsupportedError` during password sign-in when the native secure-storage
channel returns a read-only byte buffer. The adapter now returns an owned,
writable copy so authentication can clear its temporary secret after use.
A regression test reproduces the engine-style read-only response; ordinary
method-channel mocks did not expose this difference.

## Local models without API tokens

The Agent token field is now optional. Empty tokens omit authentication headers.
Ollama URLs ending in `/api/tags` resolve to `/api/chat` for the Ollama format or
`/v1/chat/completions` for Chat Completions, preserving reverse-proxy prefixes.
This prevents POST requests to the GET-only model-list route. HTTP 404/405 errors
identify the POST endpoint; the Agent stops retrying unchanged requests for HTTP
401/403/404/405. Added coverage for URL mapping, empty tokens and retry behavior.
A local Ollama server accepted a token-free generation request on `/api/chat`.

## Local agent generation and verification

Added configurable local generation budgets (4096 tokens by default), temperature,
thinking preference and Auto/Schema/Object/Text response modes. Reasoning is no
longer promoted to executable actions. Malformed/truncated actions and empty
answers have bounded recovery. Empty C# projects get creation/read/finish guidance
and phase-specific schemas. See the [local-model guide](../local-model-agent.md).

## Delete project folders

The Explorer context menu now offers **Delete folder…**, with confirmation for
recursive deletion and a warning about unsaved tabs. Successful deletion closes
tabs inside that folder and preserves neighboring tabs. Workspace roots and
`.git` / `.tamtoot` paths are protected; native recursive deletion does not follow
nested symbolic links.

## Ask the desktop agent to write and run tests

Enable **Agent options → Write and run tests** on desktop. The option adds testing
instructions and an approved `run_tests` action using available SDKs. Each command
requires approval even in YOLO mode. Results include the exit code and output;
unavailable SDKs and denied commands are reported without claiming tests passed.
See [test execution and limitations](../agent-testing.md).

Latest validation: 492 regression tests passed, 3 skipped; static analysis is
clean. [Implementation files, coverage and remaining limits](0.1.8-validation.md).
