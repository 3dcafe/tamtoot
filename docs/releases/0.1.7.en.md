# Tamtoot 0.1.7: cURL import, SSH terminal fixes, and faster code editing

**Release notes in progress · updated 15 October 2026**

Tamtoot 0.1.7 improves everyday work in the free, open-source code editor and
Flutter IDE: import HTTP requests from cURL, organize API requests in folders,
open files by dragging them into the application, and use a more reliable SSH
terminal. The editor core also does less work when editing large files.

These notes describe changes in the current source tree. They are a draft,
not an announcement that updated packages are available on every platform.

[Русская версия](0.1.7.ru.md) · [Project overview and setup](../../README.md)

## HTTP request manager: import cURL commands

Use **Tools → HTTP Requests → Import cURL** to turn a pasted command into an
editable request with its HTTP method, URL, headers, and body. Review the result
and click **Save** before running it.

- Import common quoted commands, multiline commands, and Windows `curl.exe`
  commands.
- Preserve URL query parameters and support request data, cookies, and explicit
  authorization headers.
- Report unsupported options instead of silently changing the request.
- Parse the command as text; importing does not execute cURL or read local files
  referenced by the command.

This helps move an API request from a browser's “Copy as cURL” output or a
command-line example into the project request manager. Some cURL options,
including file uploads and redirect handling, are not supported by the importer.

## Organize API requests in folders

- Drag a request onto a folder to move it. Drop it on **Requests root** to move
  it back to the top level.
- In an open request, set **Folder** to a path such as `users/admin` and click
  **Save**. An empty value selects the requests root; new folders are created
  when needed.
- Move requests together with their Markdown documentation and preserve edited
  request contents when saving to a different folder.
- Keep existing files when destination names conflict; show an error so you can
  choose another location.
- Create separate files for requests with repeated names or names that produce
  the same filename, including Cyrillic names. Refresh the list after creation.

## Open files with drag and drop on Windows, macOS, and Linux

Drag files from Explorer, Finder, or a Linux file manager into the main Tamtoot
window to open them in editor tabs. Text files open for editing; supported
images use the existing preview view.

Dropping an already open file activates its tab and preserves unsaved edits.
Multiple dropped files open in sequence; an unavailable file does not prevent
the remaining files from opening. Modal dialogs do not send dropped files to
the editor behind them. **File → Open file** remains available as an alternative.

## SSH connections and terminal input

SSH profiles are easier to find through **Tools → SSH connections…** and the
toolbar's **SSH connections** button. Choose **Add SSH profile** to add a server.

- Fix physical character input in the Windows SSH terminal after focus changes.
- Support paste through Ctrl+V, Ctrl+Shift+V, Shift+Insert, and the paste button;
  macOS also supports Command+V.
- Restore input focus after terminal action buttons so typing can continue.
- Fix committed text input when an input method finishes composition without
  changing the text itself.
- Close the SSH connection and return to the previous screen when the remote
  shell exits, including after `logout` or `exit`.

## Cleaner project startup and menus

- Check restored file tabs after recovering workspace access. Close unchanged
  tabs whose files are unavailable; recover unsaved changes as drafts.
- Remove a project from **Open project** without deleting its directory. Opening
  that folder again adds it back to the list.
- Open the in-window top menus without a reveal animation.
- When a runnable project is not detected, show one **Configure project run…**
  item in **Run**, leading to SDK settings. The same shortcut is shown for a
  detected Flutter project without a configured Flutter SDK.

## Faster text buffer and document status checks

The text buffer updates affected line-index entries instead of scanning the
whole document after every edit. Cursor position calculations also avoid a
temporary line string, and the unsaved-change indicator reuses its result until
the document revision or saved snapshot changes.

In a local benchmark using a 20,000-line file, a sequence of 100 insertions was
about **1.9–2 times faster** than the previous buffer implementation. This measures
buffer operations, not whole-application speed or a guarantee for every device.
The underlying string storage still copies text during edits.

Regression checks include 1,500 randomized buffer edits, line/offset consistency,
Undo/Redo, saved-state changes, and editor interaction tests.

## Accessibility and feedback

Added an [accessibility statement](../../ACCESSIBILITY.md) describing target
platforms, current features, known limitations, and how to report barriers.
Screen reader support for the custom editor and SSH terminal remains incomplete.
An accessibility issue template and contribution guidance are also included.

For a bug or suggestion, use the
[Tamtoot issue tracker](https://github.com/3dcafe/tamtoot/issues).
Include your application version and operating system; remove credentials and
private request or server details from examples.
