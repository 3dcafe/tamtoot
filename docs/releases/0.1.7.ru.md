# Tamtoot 0.1.7: импорт cURL, исправления SSH-терминала и ускорение редактора кода

**Заметки к версии дополняются · обновлено 18 октября 2026 года**

Tamtoot 0.1.7 делает повседневную работу в бесплатном редакторе кода и Flutter IDE
с открытым исходным кодом удобнее: импорт HTTP-запросов из cURL, организация
API-запросов по папкам, открытие файлов перетаскиванием и исправления
SSH-терминала. Ядро редактора также выполняет меньше работы при правках больших
файлов.

Здесь описаны изменения текущих исходников. Это черновик заметок, а не объявление
о доступности обновлённых сборок для всех платформ.

[English version](0.1.7.en.md) · [Документация Tamtoot](../ru/README.md)

## Менеджер HTTP-запросов: импорт команд cURL

Откройте **Tools → HTTP Requests → Import cURL**, вставьте команду и получите
редактируемый запрос с HTTP-методом, URL, заголовками и телом. Проверьте результат
и нажмите **Save** перед отправкой.

- Импорт распространённых команд с кавычками и переносами строк, включая
  Windows-команды `curl.exe`.
- Сохранение параметров URL; поддержка данных запроса, cookies и явно заданных
  заголовков авторизации.
- Ошибка для неподдерживаемых параметров вместо незаметного изменения запроса.
- Команда разбирается как текст: импорт не запускает cURL и не читает локальные
  файлы, указанные в команде.

Так можно перенести API-запрос из браузерного «Copy as cURL» или примера командной
строки в менеджер запросов проекта. Часть возможностей cURL, включая загрузку
файлов и обработку перенаправлений, пока не поддерживается импортом.

## Папки для API-запросов

- Перетащите запрос на папку, чтобы переместить его. Строка **Requests root**
  возвращает запрос в корень списка.
- В открытом запросе укажите **Folder**, например `users/admin`, и нажмите
  **Save**. Пустое поле означает корень; нужные новые папки создаются при
  сохранении.
- Вместе с запросом перемещается Markdown-документация. При сохранении в другую
  папку сохраняются и правки содержимого запроса.
- При конфликте имён существующие файлы сохраняются: приложение показывает
  ошибку и позволяет выбрать другое расположение.
- Запросы с повторяющимися названиями или названиями, дающими одинаковое имя
  файла, получают отдельные файлы. Это исправляет создание нескольких запросов
  с русскими именами. Список обновляется после добавления.

## Открытие файлов перетаскиванием в Windows, macOS и Linux

Перетащите файлы из Проводника, Finder или файлового менеджера Linux в основное
окно Tamtoot. Они откроются во вкладках: текстовые файлы — для редактирования,
поддерживаемые изображения — в режиме просмотра.

Повторное перетаскивание активирует уже открытую вкладку и сохраняет несохранённые
правки. Несколько файлов открываются последовательно; недоступный файл не мешает
открыть остальные. При открытом модальном диалоге файлы не попадают в редактор
под ним. Альтернативный способ — **File → Open file**.

## SSH-подключения и ввод команд в терминале

SSH-профили теперь проще найти: **Tools → SSH connections…** или кнопка
**SSH connections** на панели инструментов. Для добавления сервера нажмите
**Add SSH profile**.

- Исправлен ввод обычных символов с клавиатуры в SSH-терминале Windows после
  смены фокуса.
- Вставка через Ctrl+V, Ctrl+Shift+V, Shift+Insert и кнопку Paste; на macOS также
  доступно Command+V.
- После кнопок терминала фокус возвращается к вводу, чтобы продолжить команду.
- Исправлена отправка текста после завершения композиции методом ввода, когда
  меняется состояние ввода, но сам текст остаётся прежним.
- После завершения удалённой оболочки, в том числе командами `logout` или `exit`,
  SSH-соединение закрывается и приложение возвращает на предыдущий экран.

## Восстановление проекта и удобство меню

- При запуске сохранённые вкладки проверяются после восстановления доступа к
  папкам проекта. Неизменённые недоступные файлы закрываются, а несохранённые
  изменения восстанавливаются как черновики.
- Проект можно убрать из **Open project**, сохранив папку на диске. Повторное
  открытие папки возвращает его в список.
- Верхнее меню внутри окна открывается без анимации раскрытия.
- Если запускаемый проект не определён, в **Run** остаётся один пункт
  **Configure project run…**, ведущий в настройки SDK. Такой же переход доступен
  для Flutter-проекта без настроенного Flutter SDK.

## Ускорение текстового буфера и проверки несохранённых изменений

Индекс строк обновляется по месту правки вместо полного просмотра документа
после каждого изменения. Расчёт позиции курсора больше не создаёт временную
строку. Признак несохранённых изменений переиспользуется, пока не изменится
ревизия документа или сохранённый снимок текста.

В локальном замере на файле из 20 000 строк серия из 100 вставок стала быстрее
примерно в **1,9–2 раза** по сравнению с предыдущей реализацией буфера. Замер
относится к операциям буфера: результат зависит от файла и устройства и не
означает такое же ускорение всего приложения. При изменениях строковое хранилище
по-прежнему копирует текст.

Уменьшена нагрузка от восстановления сессии: перемещение курсора и выделения
больше не запускает сериализацию и запись. После первого сохранения обычный ввод
обновляет снимок документов без повторной записи неизменившихся настроек,
раскладки, горячих клавиш и учётных данных — одна запись вместо шести.
Изменённые настройки сохраняются, а неудачные записи повторяются при следующем
сохранении.

Регрессионные проверки включают 1500 случайных правок буфера, согласованность
строк и координат, Undo/Redo, изменения сохранённого состояния и работу редактора.

## Настройки профилей моделей и закреплённые кнопки

- Управление профилями моделей перенесено прямо в **Settings → Agents**:
  создание, выбор профиля для редактирования и удаление с подтверждением.
  Шаблоны OpenAI GPT и AI STAR доступны в этом же разделе.
- Отдельное окно работает с одним профилем: из формы убраны переключатель
  профилей и кнопки создания или удаления других профилей.
- Проверка соединения, поиск моделей Ollama, сброс промптов, Preview, Run,
  сохранение профиля и инструкций, а также закрытие собраны в закреплённой
  нижней панели. Для сохранения больше не нужно прокручивать форму.
- Компактные кнопки-иконки снабжены подсказками при наведении. Несохранённые
  изменения отмечаются другими иконками сохранения и текстом подсказок;
  на узких экранах панель переносится на несколько строк.

## Подсветка Dockerfile и YAML

- Автоматическое распознавание Dockerfile, Containerfile, вариантов
  `Dockerfile.dev` и файлов с расширением `.dockerfile`.
- Подсветка инструкций Docker, комментариев, переменных, параметров и строк.
- Поддержка `.yaml` и `.yml`, включая Docker Compose, Flutter `pubspec.yaml`,
  манифесты Kubernetes и GitHub Actions: ключи, строки, комментарии, числа,
  логические значения, null, якоря, ссылки и маркеры документов.
- Начальные шаблоны YAML, Compose и Dockerfile в диалоге создания файла.

Подсветка лексическая: встроенные shell-скрипты, Docker heredoc и содержимое
блочных строк YAML не имеют отдельного вложенного парсера. Добавлена поддержка
редактирования, без запуска Docker и проверки схем.
Справочники: [синтаксис Dockerfile](https://docs.docker.com/reference/dockerfile/)
и [YAML 1.2.2](https://yaml.org/spec/1.2.2/).

## Подсветка синтаксиса JSON

- Автоматическое распознавание `.json`, включая `package.json` и файлы настроек,
  на всех поддерживаемых платформах редактора.
- Раздельная подсветка ключей и строковых значений, включая экранированные кавычки
  и Unicode; подсветка чисел, логических значений, null и знаков пунктуации.
- Шаблоны JSON-объекта и массива при создании файла; автозакрытие фигурных и
  квадратных скобок, двойных кавычек.
- Незавершённая строка не нарушает подсветку следующих строк.

Добавлены редактирование и лексическая подсветка; проверка JSON Schema и
комментарии JSONC не включены.

## Редактирование C, C++ и ассемблера

- Добавлены C и C++: препроцессор, типы, ключевые слова, строки, числа,
  многострочные комментарии, raw-строки C++ с собственным разделителем,
  автозакрытие скобок и шаблоны файлов/кода. Заголовки `.h` используют пакет C++.
- Отдельные пакеты Intel/NASM/MASM, GNU AT&T, ARM и AArch64: метки, директивы,
  подсветка позиции команды, регистры и непосредственные значения. Позиционная
  подсветка работает и с новыми мнемониками или вызовами макросов, но не проверяет
  поддержку команды процессором.
- Распознаются `.asm`/`.inc`, GNU `.s`/`.S` и явные имена ARM/AArch64. Обычный
  `.s` использует GNU x86; автоматического определения архитектуры нет.
- Добавлены архитектурные шаблоны завершения программы для Linux.

Это поддержка редактирования: компиляторы, запуск ассемблера, проверка операндов
и отладчик не включены. [Диалекты и ограничения](../c-cpp-assembly.md).
