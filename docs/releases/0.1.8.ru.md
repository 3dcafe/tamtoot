# Tamtoot 0.1.8: надёжнее вход по SSH

**Примечания к выпуску дополняются · 19 октября 2026 · версия 0.1.8+8**

[English version](0.1.8.en.md) · [О проекте](../../README.md)

## Исправлен разрыв соединения сразу после успешного входа

Устранена гонка обработки пакетов: SSH-сервер может сразу за подтверждением
успешной аутентификации прислать служебный запрос, например объявление ключей
OpenSSH. Раньше клиент мог обработать этот запрос до обновления состояния входа
и закрыть соединение. Теперь состояние обновляется при получении пакета успеха,
до обработки следующих сообщений.

Проверка ключа сервера и требования к шифрованию сохранены. Новые способы
аутентификации или криптографические алгоритмы в этом исправлении не добавлялись.

## Понятнее причины отключения

Если транспорт сохранил причину сбоя, активная SSH-операция получает её вместо
общего сообщения о закрытом соединении. Это помогает отличить проблемы
транспорта от отказа при проверке учётных данных.

## Проверка

- Добавлен регрессионный тест служебного сообщения OpenSSH сразу после успешного
  входа и тест передачи причины транспортного сбоя активной команде.
- Добавлена необязательная диагностика LAN-сервера. Она использует доверие ключу
  только в памяти, запрашивает доступные методы входа и не передаёт пароль,
  приватный ключ, команды или запрос на открытие оболочки. По умолчанию отключена.
- На локальном сервере OpenSSH 10 проверены обмен ключами, шифрование и ответ
  сервиса аутентификации. Полный вход и интерактивный терминал требуют проверки
  пользователем с его учётными данными.

Пример запуска диагностики собственного сервера:

```sh
TAMTOOT_SSH_DIAGNOSTIC_HOST=192.0.2.1 TAMTOOT_SSH_DIAGNOSTIC_USER=example flutter test --no-pub test/ssh_lan_diagnostic_test.dart
```

Документ описывает изменения в исходном коде, а не опубликованную сборку магазина.

Результат проверки: статический анализ без замечаний. Полный прогон: 460 тестов
прошли, 2 пропущены, один тест PTY с `top` не дождался начального вывода. При
отдельном повторе этот тест прошёл; исходный полный прогон не был чистым.

## Ввод пароля и диагностика входа

Если защищённое хранилище не отдаёт сохранённый пароль, клиент предлагает
ввести его вручную, сохраняя профиль и сохранённые учётные данные.
Неожиданные ошибки входа теперь содержат этап аутентификации и тип ошибки.
Исходный текст исключения провайдера не показывается, чтобы не раскрывать
учётные данные. Добавлены тесты недоступного хранилища и безопасной диагностики.

## Исправлено использование сохранённого пароля

Устранён `UnsupportedError` при входе с паролем из защищённого хранилища.
Нативный канал может возвращать неизменяемый массив байтов. Теперь адаптер
возвращает отдельную изменяемую копию, которую можно очистить после отправки.
Добавлен тест с неизменяемым ответом платформы: обычные моки канала
эту особенность нативной сборки не воспроизводили.

## Локальные модели без токена

Поле токена агента теперь необязательно. При пустом токене заголовки авторизации
не отправляются. Адрес Ollama `/api/tags` преобразуется в `/api/chat` для формата
Ollama или `/v1/chat/completions` для Chat Completions, с сохранением префикса
прокси. Это устраняет отправку POST на маршрут списка моделей, принимающий GET.
Ошибки 404/405 показывают адрес запроса; агент больше не повторяет неизменённые
запросы при HTTP 401/403/404/405. Добавлены тесты адресов, пустого токена и повторов.
Локальный сервер Ollama принял запрос генерации на `/api/chat` без токена.
