# TamToot 0.1.6

## Editor

- Enter preserves indentation and adds an indentation level after a language block opener. Enter between adjacent braces creates an indented blank line.
- Automatically close brackets and quotes, wrap selected text, skip an existing closing delimiter, and remove empty pairs with Backspace.
- Toggle comments using **Ctrl/⌘+/**, **Edit → Toggle comment**, or the editor context menu. Line and block comments follow the selected language.
- Editing actions preserve Undo/Redo and selections; composing IME input remains literal.

## C# and Dart

- Added code-template suggestions with descriptions. Accept a suggestion with Tab, Enter or a click; multiline templates retain the current indentation and can be undone in one step.
- Added 12 C# templates, including properties, constructors, interfaces, loops, try/catch, switch expressions and console output.
- Added 10 Dart templates, including loops, enums, extensions, switch expressions, StatefulWidget, initState and dispose.
- Template suggestions also work in standalone files. Suggestions are hidden in strings, comments and composing IME input.
- Improved project completion for generic methods, nullable member access, and members of records, structs, enums and mixins. Generic method signatures keep their type parameters.
- Highlight member properties, generic calls, C# built-in types, literals and string interpolation. Dart named arguments also have a separate color. Both bundled themes support the new colors.
- Unfinished ordinary Dart strings no longer affect highlighting on subsequent lines.

## Java and Kotlin

- Added project completion for Java (`.java`) and Kotlin (`.kt`, `.kts`): methods, fields, local declarations and parameters, including Kotlin nullable member access.
- Added 12 templates per language, with descriptions, indentation and single-step Undo; available in standalone files too.
- Highlight generic calls and member properties, Kotlin named arguments, literals and string templates, including multiline raw strings.
- Unfinished ordinary strings no longer affect subsequent lines. Suggestions remain hidden in strings and comments.

## TypeScript and Angular

- Added project completion for `.ts`, `.tsx`, `.mts` and `.cts`: typed members and parameters, generic functions and nullable member access.
- Added 12 TypeScript templates; improved property, primitive-type, generic-call and template-string highlighting. Backticks pair and skip existing closers.
- Angular templates activate only when root `angular.json` contains a projects map or root `package.json` declares `@angular/core` in dependencies/devDependencies. Invalid manifests and unrelated projects do not activate them.
- Added 10 TypeScript Angular templates (components, services, directives, pipes, lifecycle hooks, injection and signals) and 5 HTML templates (control flow and bindings).
- Full declaration templates include imports. Smaller API snippets state required imports in their descriptions; imports are not inserted automatically. Modern Angular APIs require a compatible project version.
- Angular support remains template based; compiler-backed template diagnostics and component binding resolution are not included. Templates follow [Angular component documentation](https://angular.dev/api/core/Component) and [signal input documentation](https://angular.dev/guide/components/inputs).

## PHP and React

- Added a bundled PHP language package for `.php`, `.phtml`, `.php8`: syntax highlighting, comments, bracket/quote pairing, class/script file templates and 12 code templates.
- PHP project suggestions include methods, typed properties, variables and parameters; member access supports `->`, `?->` and `::`.
- Recognize `.jsx` as JavaScript. React templates activate when root `package.json` declares `react` in dependencies/devDependencies, and deactivate after dependency removal and index refresh.
- Added 10 React templates for JavaScript and TypeScript: components, hooks, lists and fragments. Hooks show required imports; no automatic imports or JSX semantic analysis are added.
- Templates follow the official [React hooks documentation](https://react.dev/reference/react/hooks) and [PHP type declarations](https://www.php.net/manual/en/language.types.declarations.php). PHP support covers editing; a PHP runtime/debugger is not included.

## Editor performance

- Cache folding regions by document revision and language; reuse the visible-line map until folding or document contents change.
- Reuse native text layouts, including line numbers, in a bounded 256-entry LRU cache. Evicted layouts are disposed; text, tokens, theme, font and tab size participate in cache keys.
- Pass changed-line ranges to syntax caches instead of comparing the entire cached prefix after each edit. Undo/Redo, reload and batches participate in the same bounded edit history.
- Incrementally update active-file completion with parser state checkpoints. Reuse unaffected lines once the parser state converges; scope changes and line insertions/deletions may require reparsing the remaining suffix.
- Added regression checks with 10,000-line buffers, layout reuse/invalidation and incremental/full-parser equivalence across supported completion languages. These checks verify work avoided; they are not a device FPS benchmark.

## Dart and Flutter convenience

- Flutter layout actions in Edit, context menu and command palette: wrap a selected complete widget expression in Padding, Center, Expanded, Column or Row; remove common wrappers around a single constructor child. Multiple children and incomplete selections are rejected. Wrapping uses one Undo step, respects indentation/trailing commas, preserves multiline literals and retains implicit const when unwrapping.
- Argument value hints include alignment enums, EdgeInsets, colors, text overflow/direction, clipping, flex fit and booleans. Qualified and member prefixes work; accepting a value replaces the entire prefix. Values are examples from a curated catalog; no automatic imports or type analysis are added.
- These new layout actions and value hints require unrestricted, unprefixed Flutter UI imports. Colors requires material.dart. Removing a wrapper discards its layout properties; Expanded needs a suitable Flex parent.
- Ctrl+Space requests completion explicitly. Indexed Dart functions offer named arguments with types and required markers; already supplied arguments are omitted.
- Files importing `package:flutter/...` get argument hints for 14 common Flutter constructors, including Container, Text, Row/Column, Scaffold, FutureBuilder and LayoutBuilder. Works without an open project; Tab/Enter inserts `name: ` and Undo reverses insertion.
- Dart indexes multiline function signatures and default/named constructors, including generic types, callback parameters and comments inside parameter lists. Pending signatures are bounded to 16,384 characters and participate in incremental parser checkpoints.
- Accepting a Dart function before an existing `(` preserves the parentheses and moves the cursor inside the call; Undo restores the original text. The completion cache format is updated to rebuild old indexes.
- Seven new templates: constructor, copyWith, toJson, fromJson, futureBuilder, layoutBuilder and setState. Adapt example names; imports are not inserted automatically.
- Call context scanning is bounded to the nearest 8,192 characters. These are limited syntax hints: overload resolution and the full SDK API are not supported yet.

## Project naming conventions

- Added Settings → Project naming: per-language presets for types, functions, variables, properties and constants; editable camelCase, PascalCase, snake_case, UPPER_SNAKE_CASE, combined styles and No check.
- Profiles persist locally for each project URI. Reset a language to defaults or disable advice for the project; other projects are unaffected.
- Recognized naming violations receive theme-aware green underlines and an expected-style message in the caret's context menu. Compiler error colors are preserved; nothing is renamed automatically.
- Debounced incremental checks reuse unchanged declaration/token states. Comments, strings, explicit overrides and Python magic names are excluded. [Presets and lexical limitations](../naming-conventions.md).

All changes use the existing native Dart/Flutter implementation; no additional dependencies were added. Completion and highlighting remain syntax based: full compiler-backed IntelliSense, automatic imports and semantic refactoring are not included.

Validation: **398 tests passed, 1 skipped**; `flutter analyze` reported no issues. [Verification details](../verification.md).
