# 0.1.8 implementation and verification notes

Updated 20 October 2026. This report covers local-model agent improvements,
project-folder deletion and optional desktop test execution.

## Coding-agent loop regression checks (20 October)

- Full non-benchmark suite: **516 passed, 3 skipped**.
- After the final search-version and task-scope refinements: **67 agent tests passed**.
- The focused set includes **19 loop/recovery scenarios** with a complete Flutter fixture.
- Static analysis and `git diff --check` passed.

`test/agent_loop_recovery_test.dart` exercises a complete, valid Flutter source
fixture at `lib/pages/components/cardVisit.dart`: find it, read the range, change
two button styles, preserve both `onPressed` callbacks and all other source,
read the changed version and finish without creating unrelated files. Further
cases cover identical reads, external file changes, forbidden search schemas,
replacement-retry exhaustion, placeholder paths, task-scoped creation,
verification of the changed range and action/no-progress budgets.

Default local limits are 32 accepted action attempts and 8 turns without
progress, within the existing 40-iteration cap. Local reads return up to two
files and 60 lines per file, with a 4,000-character excerpt cap. Explicit test
requests may create test files; other new files in an existing project must be
named in the task. New-project scaffolding remains supported.

Ollama tests mock the compatibility reasoning-only response, native `/api/chat`
recovery, `think: false`, rejection of that parameter, the 800-token recovery
budget and bounded empty replies. They do **not** establish that any particular
live Ollama model follows the protocol or produces correct Flutter code.

## Practical limits

Mocked generation establishes protocol behavior, not the accuracy of an arbitrary
model's code. Earlier live attempts exposed missing action fields and repeated
writes/listing; schemas and scaffold-phase restrictions now constrain these paths.
The final live attempt could not be completed because the LAN Ollama endpoint
stopped accepting connections. No successful live C# generation/build is claimed.

Native deletion and the confirmation flow were tested on the development host.
Browser directory deletion was statically checked; no interactive browser-file-picker
check was performed. Windows/mobile UI behavior was simulated in widget tests.
Actual SDK execution still depends on installed tools and app sandbox permissions.
Windows batch-only runners are intentionally not invoked through cmd.exe.
