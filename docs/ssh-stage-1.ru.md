# SSH: этап 1 — профили и ключи

Реализация первого этапа доступна в **Tools → Settings → SSH connections**.
Профили не требуют открытого проекта и сохраняются в пользовательских настройках
IDE. В проект, `.tamtoot` и настройки попадает только ссылка на сохранённый секрет,
а не сам секрет. Новых зависимостей в `pubspec.yaml` нет; SSH-код не использует
существующий пакет `crypto` и не запускает внешние программы.

## Возможности

- Добавление, редактирование и подтверждаемое удаление профиля: имя, сервер,
  порт (1–65535), пользователь, пароль или приватный ключ.
- По умолчанию профиль пароля сохраняется без пароля. Подключения и запрос
  пароля при подключении относятся к следующим этапам.
- Импорт одного незашифрованного приватного ключа Ed25519 в контейнере
  `OPENSSH PRIVATE KEY`, максимум 64 KiB. Проверяются magic, длины, алгоритм,
  отсутствие cipher/KDF, checkints, совпадение открытых частей и padding.
- Проверка импорта является проверкой структуры: соответствие seed открытому
  ключу криптографически ещё не проверяется. Это относится к криптографическому
  этапу перед использованием ключа для подписания.
- RSA, PEM/PKCS#8, публичные ключи и зашифрованный OpenSSH отклоняются с понятной
  ошибкой. Генерация ключей и парольные фразы пока отсутствуют.
- Сохранение нового секрета требует отдельного флажка. Без него секрет живёт
  в памяти текущего экземпляра IDE. При перезапуске ключ нужно импортировать снова.
- Поля секрета при редактировании не заполняются сохранёнными значениями.
  Отдельный флажок удаляет существующий секрет. Смена способа входа удаляет старый.

## Платформы

| Платформа | Постоянное хранение | Без сохранения |
| --- | --- | --- |
| macOS / iOS | Keychain, `WhenUnlockedThisDeviceOnly`, без синхронизации | Память сеанса |
| Android | AES-GCM через системные API; неэкспортируемый ключ Android Keystore; шифротекст в `noBackupFilesDir` | Память сеанса |
| Windows | Windows Credential Manager, generic credential; системный лимит размера секрета | Память сеанса |
| Linux | Пока недоступно: обязательного системного хранилища нет; обычный файл не используется | Память сеанса |
| Web | SSH-раздел скрыт; браузерная сборка вне плана | — |

Ошибка нативного хранилища не приводит к записи открытого секрета в файл или
SharedPreferences. Пользователь видит ошибку и может повторить операцию либо
сохранить новый секрет только в сеансе.

Сохранение профилей выполняется последовательно. Перед записью нового постоянного
секрета сохраняется намерение очистки; после привязки нового секрета старый
помечается для удаления. При прерывании операции или ошибке удаления очистка
повторяется при загрузке SSH-раздела. Неудачная очистка показывает предупреждение
и не блокирует сессионный режим. Метаданные содержат только случайные ссылки.
Ошибка удаления профиля оставляет его доступным для повторной попытки.
Временные байтовые буферы очищаются, где это возможно; Dart/Flutter и платформенные
каналы создают копии строк и буферов, поэтому полного гарантированного удаления
всех копий из памяти эта реализация не обещает.

Формат контейнера сверяется с
[OpenSSH PROTOCOL.key](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL.key).

SSH transport, проверка ключа сервера, аутентификация, команды, терминал и SFTP
в этом этапе отсутствуют. Реализация рассчитана на нативные платформы, но сборка
на одной ОС не подтверждает работу хранилищ на остальных: нужны отдельные проверки
на Windows, Linux и мобильных устройствах.

## Проверка реализации

- 14 новых тестов: CRUD и восстановление, отсутствие секретов в JSON,
  сессионный режим, смена/удаление секретов, откат неудачной записи,
  отложенная очистка при недоступном хранилище, ограничения парсера,
  обрезанные контейнеры и неверные длины, нативный канал и интерфейс на ширине 430 px.
- Полный набор: 238 тестов прошли, один пропущен; Dart analyzer без замечаний.
- Финальная macOS debug-сборка успешна.
- Swift-код iOS проверен `swiftc -typecheck` для arm64 simulator.
  Исправлена несовместимая сигнатура существующего `createArgsCodec` в preview-адаптере.
- Полный Android debug APK успешно собран Gradle в offline-режиме.
- Полная iOS-сборка не подтверждена; сборки Windows/Linux в этом окружении не запускались.
- Нативные хранилища требуют отдельной проверки CRUD на устройствах;
  тест нативного канала использует mock и не подменяет эту проверку.
