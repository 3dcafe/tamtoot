# SSH: этап 3 — вход и выполнение команд

Реализован вход по паролю, OpenSSH-ключу Ed25519/RSA и keyboard-interactive, затем выполнение команды через SSH `session/exec`. Сторонних зависимостей не добавлено: протокол на Dart, подпись и расшифровка ключей — собственный C++ модуль через стандартный Dart FFI. Приложение не запускает системный SSH.

## Использование

Откройте Settings → SSH, создайте профиль и нажмите Connect. После проверки отпечатка сервера приложение запрашивает необходимые данные входа. Для ключа можно импортировать OpenSSH-файл; парольная фраза запрашивается при разблокировке. После входа доступны поле Remote command, Run command, Cancel command и копирование результата. stdout, stderr и код завершения отображаются отдельно. Команда не выполняется повторно при переподключении.

## Поддержка и ограничения

- Ed25519; RSA 2048–4096 бит с `rsa-sha2-512` или `rsa-sha2-256`. Подписи RSA/SHA-1 не используются.
- Одноключевые OpenSSH private key: без шифрования либо `aes256-ctr` + `bcrypt`. PEM/PKCS#8, другие шифры и OpenSSH-сертификаты не поддерживаются. Контейнер ограничен 64 КиБ, соль bcrypt — 8–64 байта, число раундов — 1–128.
- До шести запросов с учётными данными/ключом за соединение. Keyboard-interactive: до восьми раундов, 16 вопросов за раунд и 64 суммарно. Поддерживается частичная аутентификация. Смена пароля по запросу сервера не реализована.
- До четырёх каналов; входное окно 256 КиБ, пакет данных до 32 КиБ, очередь stdin до 1 МиБ. Передача ждёт увеличения окна сервера.
- Совокупный stdout/stderr ограничен 2 МиБ. Превышение лимита считается ошибкой; усечённый вывод не выдаётся за успешный результат. Интерфейс показывает до 256 КиБ каждого потока, кнопка копирования использует полный полученный результат.
- Тайм-аут команды по умолчанию 60 секунд. API допускает до часа. Успех определяется кодом завершения после закрытия канала; EOF сам по себе недостаточен.
- Отмена закрывает канал и снимает ожидания. Она **не гарантирует остановку удалённого процесса**. Отсутствие подтверждения закрытия за пять секунд закрывает соединение.
- Парольные фразы, ответы challenge и команды не сохраняются в проект, историю агента или журналы. Рабочие байтовые буферы очищаются после использования. Dart/Flutter не гарантируют стирание всех копий строк из управляемой памяти. Сохранение пароля/ключа использует хранилище этапа 1; Linux имеет только хранение на время сессии.

## Архитектура

`lib/core/ssh/ssh_client.dart` владеет потоком сообщений транспорта, аутентификацией и таблицей каналов. `auth/ssh_authentication.dart` реализует методы входа, `auth/ssh_private_key.dart` проверяет и разблокирует ключи, `channels/ssh_exec_channel.dart` управляет окнами, stdout/stderr, stdin, EOF и закрытием. Проверка сервера предшествует запросу секретов.

`native/ssh/ssh_auth_crypto.inc` реализует Ed25519 и RSA PKCS#1 v1.5/SHA-2. Закрытые скаляры не передаются в Dart BigInt. RSA проверяет соответствие параметров ключа и подпись публичным показателем перед возвратом. `ssh_bcrypt.inc` реализует bcrypt_pbkdf; константы Blowfish воспроизводятся скриптом `generate_blowfish_constants.py` из цифр π. Дорогая подпись и KDF выполняются в стандартных Dart isolates. Освобождение native signer откладывается до завершения активной операции.

Собственная криптография не проходила независимый аудит. Фиксированное число операций в некоторых примитивах не является доказательством отсутствия побочных каналов; в bcrypt используются индексируемые таблицы Blowfish.

## Проверка

Тесты `ssh_client_openssh_test.dart` запускают изолированный тестовый OpenSSH и временные ключи: Ed25519/RSA, открытые и зашифрованные контейнеры, RSA 3072/4096, показатель по lcm, вывод обоих потоков, код 7, повторная команда, 512 КиБ stdin с rekey, неверный ключ/фраза, лимиты попыток/вывода и тайм-аут. Системные `sshd`/`ssh-keygen` используются только тестами. Реальный пароль пользователя и его личные ключи не используются.

Протокольные тесты проверяют пароль и keyboard-interactive, очистку буферов, partial success, привязку подписи к session ID, проверку PK_OK, окна stdin, отмену открытия и ошибочные последовательности. Вход паролем/keyboard-interactive проверен на моделируемом сервере, а не на реальной системной учётной записи. Виджеты проверены при ширине 430 px. Нативные векторы RFC 8032 и bcrypt_pbkdf проверяются отдельно, включая освобождение signer во время фоновой работы.

Команды воспроизведения:

```sh
flutter analyze
flutter test
clang++ -std=c++17 -O1 -g -fsanitize=address,undefined -fno-omit-frame-pointer native/ssh/ssh_crypto_sanitizer_test.cpp -o /tmp/tamtoot-ssh-sanitizer
/tmp/tamtoot-ssh-sanitizer
flutter build macos --debug
flutter build ios --simulator --debug
```

Итоговые результаты сборок и полного набора тестов записаны в [verification.md](verification.md). Windows/Linux и физические устройства требуют отдельной проверки. Интерактивный терминал с PTY относится к этапу 4, SFTP — к последующим этапам.

Спецификации: [RFC 4252](https://www.rfc-editor.org/rfc/rfc4252.html), [RFC 4254](https://www.rfc-editor.org/rfc/rfc4254.html), [RFC 4256](https://www.rfc-editor.org/rfc/rfc4256.html), [RSA SHA-2 — RFC 8332](https://www.rfc-editor.org/rfc/rfc8332.html), [формат ключей OpenSSH](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL.key).
