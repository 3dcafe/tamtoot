# HTTP-запросы

[← Оглавление](README.md)

Откройте вкладку **Requests** рядом с Solution и Git или выберите **Tools → HTTP Requests…**. Запросы можно распределять по вложенным папкам, создавать, редактировать, переименовывать, перемещать, удалять и запускать по одному или выбранным набором.

## Поддерживаемые данные

- Методы: GET, POST, PUT, PATCH, DELETE, HEAD и OPTIONS.
- Отдельно включаемые query-параметры и заголовки.
- Тело JSON, обычный текст и `application/x-www-form-urlencoded`.
- Bearer-авторизация: наследовать настройки проекта, отключить или переопределить для запроса.
- Последовательный запуск с остановкой при ошибке или параллельный запуск максимум пяти запросов.

Результат показывает HTTP-статус, длительность и ограниченный предпросмотр ответа.

## Переменные окружения

Выражения `{{variable}}` разрешаются в URL, query-параметрах, заголовках, теле и токене. Приоритет значений:

1. значения, переданные на время запуска;
2. локальные секреты;
3. общие переменные проекта.

Общие переменные находятся в `.tamtoot/environment.json`, локальные секреты — в `.tamtoot/environment.local.json`. Если в настройку проекта или запроса введён буквальный bearer-токен, Tamtoot переносит его в локальное окружение, а в общий JSON записывает ссылку `{{variable}}`.

## Совместная работа

```text
.tamtoot/
├── requests/
│   └── ...
├── environment.json
└── environment.local.json
```

Файлы запросов из `.tamtoot/requests/**` и `.tamtoot/environment.json` видны во встроенной Git-панели. Их можно коммитить вместе с проектом и передавать другим разработчикам. `.tamtoot/environment.local.json` исключён из операций встроенного Git-клиента и добавлен в `.gitignore` репозитория, поэтому секреты остаются на компьютере разработчика.

Документация запроса хранится как обычный Markdown рядом с запросом. **New Documentation** создаёт новый файл, а **Attach Markdown** подключает существующий соседний `.md`.

Запросы и окружения используют JSON-схему версии 1. Неизвестные версии и пути за пределами проектных каталогов отклоняются.
