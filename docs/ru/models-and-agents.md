# Модели и агенты

[← Оглавление](README.md)

## Профили моделей

Откройте проект и перейдите в **Tools → Settings → Model profiles and prompts**. Для нового профиля выберите Ollama, LM Studio, LocalAI, OpenAI или Anthropic. Tamtoot заполнит стандартный endpoint и формат API; дополнительные поля находятся в **Advanced connection settings**.

Поддерживаемые форматы:

| Формат | API |
| --- | --- |
| `ollama` | Ollama Chat |
| `chat-completions` | OpenAI-совместимый Chat Completions |
| `responses` | OpenAI Responses |
| `anthropic` | Anthropic Messages |

Кнопка **Check connection** проверяет доступность и совместимость без отправки промта, а при поддержке API загружает список моделей. Для Ollama кнопка **Detect Ollama** использует `/api/tags` и `/api/show`; запросы отправляются потоково через `/api/chat`.

Профиль содержит системный промт, пользовательский шаблон и необязательный JSON параметров. Переменные шаблона: `{{task}}`, `{{file_path}}`, `{{file}}`, `{{selection}}`. Подстановка выполняется один раз, поэтому текст файла не интерпретируется как новый шаблон.

**Preview prompts** показывает итоговый промт локально. **Run model…** отправляет запрос. API-ключ хранится только в памяти до завершения запроса или закрытия окна и удаляется из отображаемых ошибок.

## Свой OpenAI-совместимый сервер

Выберите **Custom compatible API**. В поле **Server URL** можно вставить базовый
адрес, URL списка моделей `/v1/models` или полный endpoint
`/v1/chat/completions`. Tamtoot сам преобразует адрес списка моделей в endpoint
генерации. **Check connection** загружает список моделей из ответов с полем
`data` или `models`, предлагает выбрать модель и показывает итоговый адрес.

Проверенная конфигурация:

```text
Model server: Custom compatible API
Server URL: https://ai.qird.ru/v1/models
API compatibility format: Chat Completions
Model: /home/latin/models/bonsai/Ternary-Bonsai-2-27B-PQ2_0.gguf
API parameters: {"temperature": 0.2, "max_tokens": 2048}
```

Нажмите **Check connection**, выберите найденную модель, задайте Display name и
сохраните профиль. **Run model…** отправляет одиночный запрос. Для работы с кодом
проекта откройте вкладку **Agent** и выберите сохранённый профиль. Если сервер
доступен без авторизации, поле API key оставьте пустым.

## AI STAR

При создании профиля нажмите **Add AI STAR agent** или выберите сервер
**AI STAR · compatible API**. Tamtoot автоматически укажет базовый адрес
`https://ai.starimg.ru/v1`, формат Chat Completions и модель для программирования
`gpt-6.1-sol`. Вставьте токен сервиса во временное поле **AI STAR token** и
нажмите **Check connection** — список доступных вашему аккаунту моделей загрузится
с сервера. Сохраните профиль, откройте вкладку **Agent**, выберите этот профиль и
отправьте задачу — сохранённый токен подставится автоматически.

Токен общий для редактора профиля, одиночного запроса и Agent. Достаточно один раз
ввести его при проверке или сохранении профиля: Tamtoot сохранит его в локальных
настройках приложения для этого профиля. Токен не записывается в `.tamtoot`,
проект или Git. Кнопка **Forget token** удаляет его с устройства. Если основной
домен недоступен, можно указать `https://ai.starimg.space/v1`.

## Быстрый запуск с Ollama

1. Запустите Ollama и загрузите модель, например `ollama pull qwen3-coder`.
2. Откройте Git-проект в Tamtoot.
3. Создайте профиль Ollama с адресом `http://localhost:11434/api/chat`.
4. Нажмите **Detect Ollama**, выберите модель и сохраните профиль.
5. Используйте **Run model…** для одиночного запроса или **Tools → Agent…** для задачи с инструментами.

## Агент

Агент выполняет ограниченный цикл структурированных действий: перечисляет файлы, ищет совпадения по путям и тексту, читает файл целиком или по диапазону строк, точечно заменяет уникальный фрагмент, заменяет содержимое файла, вызывает подключённый MCP-инструмент, пишет статус и завершает задачу.

Пути должны оставаться внутри проекта. Через инструменты агента нельзя читать или менять `.git` и `.tamtoot`. Размеры файлов и ответа ограничены. В каждый запрос добавляется явное пояснение: Tamtoot — мобильная IDE без терминала, интерпретатора, компилятора, отладчика, сборщика и запуска тестов. После записи агент проверяет результат повторным чтением файла и завершает задачу без попыток что-либо запустить.

В обычном режиме запись файла и MCP-вызов требуют подтверждения. **YOLO Mode** автоматически подтверждает эти действия после предупреждения и проверки чистого Git-дерева. Если модель всё же предложит `run_command`, действие будет пропущено без запуска процесса. Ограничения путей, времени, количества итераций и ошибок сохраняются. Выполнение можно остановить кнопкой **Stop**.

Каждая задача сразу идёт в режим реализации: модель должна начинать с полезного
инструмента, а не с отдельного планового `say`. Короткие статусы допустимы, но
повторный `say` без инструментов отклоняется.

Контекст передаётся поэтапно. Пользовательские вложения и компактный индекс
файлов проекта отправляются с первым запросом. Дальше модель сужает область
через литеральный `search_files` (конкретные символы/идентификаторы, а не
описания на естественном языке), просмотр каталогов и чтение диапазонов строк.
Хост ограничивает подряд идущие поиски (максимум 2 с последнего чтения/правки),
мягко отклоняет повторные/похожие запросы в пересекающемся пути (с known matches,
без ошибки mistake) и после ≤4 файлов реализации требует `read_files`/`read_file`
перед новым поиском. Чтение без явного диапазона берёт контекст вокруг match,
а Active file context держит до шести увеличенных фрагментов. Последние
результаты поиска и списки файлов сохраняются в ограниченной истории.
Для небольших правок агент заменяет точный уникальный фрагмент и не
пересобирает весь большой файл. Старый контекст удаляется только при достижении
общих лимитов, поэтому агент помнит ход исследования без повторной отправки
всего проекта.

На десктопе Agent видит все папки, подключённые через **File → Add folder to
workspace…**. Пути основного проекта остаются обычными относительными путями, а
дополнительные корни получают уникальные префиксы `@имя-папки/`, показанные в
индексе проекта. Для записи действуют те же подтверждения; YOLO перед началом
проверяет чистоту всех подключённых Git-репозиториев.

До первой правки действует бюджет расследования (по умолчанию: до 5 поисков, 8 чтений файлов
и 12 итераций модели). После двух поисков и двух чтений без правки хост подсказывает перейти к
`replace_in_file`, `write_file` или одному точечному чтению. При исчерпании бюджета
`search_files`, `list_files` и `say` мягко отклоняются, а чтение и правки остаются
доступными: последнее чтение хост сам сужает до 3 файлов по 160 строк вместо отказа.
Слишком широкие или выходящие за границы файла запросы на чтение нормализуются так же —
лишние пути отбрасываются, диапазон строк обрезается, — потому что отказ стоил бы
ещё одного обращения к модели ради той же, но меньшей просьбы.

Бюджет ответа намеренно маленький: 700 токенов на навигационное действие и 1600 на
правку — одного JSON-объекта это с запасом. Бюджет отправляется под тем ключом,
который ожидает выбранный формат API (`max_tokens`, `max_output_tokens` или
`num_predict` у Ollama), вместе с документированными для этого формата
переключателями отключения thinking, а для Chat Completions ещё и JSON mode.
Если ответ всё равно приходит с пустым `message.content` (типично для thinking-сборок,
которые забивают `reasoning_content` до лимита), Tamtoot делает один дешёвый recovery
запрос: только строка задачи, требуемая фаза, разрешённые действия и известные
релевантные файлы. Неудавшийся reasoning модели не возвращается, а сам retry
не считается ошибкой, если он успешен.

Постоянная память проекта хранится в `.tamtoot/agents/project_memory.json`.
Она обновляется после успешного `finish` и при досрочной остановке (лимит ошибок,
лимит итераций, timeout, Stop), чтобы прерванное расследование не начиналось заново.
Запись компактная: файлы, связи, правки, fingerprint. В следующую задачу
подмешивается только релевантный срез — закреплённый в начале промта, где его не
вытеснят свежие наблюдения, — плюс заметка с известными файлами, которые нужно
прочитать вместо поиска. Память может пропускать повторный поиск по уже
известным местам, но перед правкой модель всё равно должна прочитать актуальный
фрагмент. Секреты вычищаются, размер документа ограничен (~8k символов) с
автоматическим compaction.

## Командная строка

```sh
TAMTOOT_API_KEY=... dart run bin/ide_agent.dart \
  --profile local-code \
  --timeout 600 \
  --max-consecutive-mistakes 3 \
  "исправь падающие тесты"
```

Флаг `-y` включает YOLO, `--json` выводит события JSON Lines, а данные из stdin добавляются к контексту задачи. Код возврата: 0 — успех, 1 — ошибка выполнения, 2 — неподдерживаемый репозиторий или отсутствующий профиль, 64 — неверные аргументы.

## Хуки и MCP

Исполняемые хуки располагаются в `.tamtoot/hooks/` и называются `TaskStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse` или `TaskCancel`. Они получают JSON через stdin и могут вернуть `cancel`, `errorMessage` и `contextModification`. Тайм-аут — 10 секунд.

MCP-серверы настраиваются через **Tools → Settings → MCP servers** в `.tamtoot/mcp.json`. Поддерживаются STDIO на системах с запуском процессов и Streamable HTTP/SSE. Удалённый HTTP требует HTTPS, localhost может использовать HTTP. Заголовки сохраняются обычным текстом, поэтому постоянные секреты в этот файл записывать не следует.

## Kanban и worktree

**Tools → Agent Kanban…** хранит карточки в `.tamtoot/agents/kanban.json`. Колонки: Todo, In Progress, Review и Done. Карточка может зависеть от других карточек.

Запуск готовой карточки на Desktop создаёт Git worktree `.tamtoot/worktrees/<card-id>` с веткой `tamtoot/<card-id>`. Автоматический планировщик зависимостей, отдельные процессы агентов для карточек, автокоммит, push и создание pull request пока не реализованы.
