# Запуск .NET на десктопе

На Windows, Linux и macOS Tamtoot запускает проекты C# через установленный .NET SDK. Дополнительный плагин не нужен. На мобильных платформах эти настройки и команды скрыты.

## Настройка SDK

В Settings → .NET SDK можно указать абсолютный путь до `dotnet` / `dotnet.exe` или каталога установки SDK. Кнопка Browse SDK выбирает каталог. Пустое поле включает автоматический поиск: `DOTNET_HOST_PATH`, `DOTNET_ROOT`, варианты `DOTNET_ROOT_X64` / `DOTNET_ROOT_ARM64`, `PATH`, пользовательский `.dotnet` и стандартные каталоги установки. Tamtoot использует окружение своего процесса: после изменения переменных перезапустите приложение. Явный путь имеет приоритет; ошибочный путь не заменяется автоматически другим SDK.

Test .NET выполняет `dotnet --list-sdks` и показывает выбранный исполняемый файл и установленные SDK. Проект при проверке не собирается. Для запуска нужен SDK, одного runtime недостаточно. `global.json` проекта может требовать другую версию SDK; ошибка выбора версии появится в Output при запуске.

## Определение проекта и запуск

При открытии папки и обновлении Solution Tamtoot ищет `pubspec.yaml` с зависимостью `flutter: sdk: flutter` и файлы `.csproj`. Поиск ограничен четырьмя уровнями вложенности и 150 каталогами; служебные каталоги сборки исключены. Тип и путь найденного проекта показаны в панели запуска. При нескольких проектах, в том числе смешанном репозитории Flutter / C#, выберите нужный в списке. Кнопка обновления повторяет поиск. Если признаков недостаточно, показано Project type not detected.

Для C# признак запускаемого проекта — `OutputType` Exe / WinExe или Web SDK. Библиотеки и проекты с типом, определяемым импортированными MSBuild-файлами, отмечены как library / run type unknown. Автоматическая кнопка Run для них отключена; можно вручную попробовать Run → Run .NET для выбранного `.csproj`.

Run сохраняет изменённые документы и выполняет `dotnet run --project <file.csproj> --configuration Debug` в каталоге проекта. Watch выполняет `dotnet watch --project <file.csproj> run --configuration Debug`; SDK сам отслеживает изменения и применяет hot reload там, где он поддерживается. Вывод и ошибки появляются в Output, Stop останавливает процесс. Терминальный ввод для интерактивных консольных программ пока не предоставляется.

## Ограничения отладки

Конфигурация Debug создаёт отладочную сборку, но не подключает отладчик. В .NET SDK нет встроенного DAP-адаптера, аналогичного Flutter. Поэтому запуск и watch работают без дополнительных компонентов, а точки останова, пошаговое выполнение и просмотр переменных C# потребуют отдельного адаптера отладки. Tamtoot не скачивает и не устанавливает его автоматически.

Сам запуск может собирать проект и восстанавливать NuGet-пакеты. Нужны SDK соответствующей версии и зависимости проекта; для некоторых типов приложений — платформенные инструменты или workloads. Определение типа и Test .NET сборку не запускают.
