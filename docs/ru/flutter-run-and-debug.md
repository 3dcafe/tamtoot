# Запуск и отладка Flutter в Tamtoot

Настройки SDK и команды Flutter доступны только в настольном Tamtoot на Windows, Linux и macOS. На Android, iOS и Web они скрыты. Дополнительный плагин или другая IDE не нужны: Tamtoot подключается к отладчику, поставляемому с вашим Flutter SDK.

## Настройка SDK и проверка

1. Установите Flutter SDK и инструменты сборки нужной платформы. Для macOS требуется Xcode, для Windows — Visual Studio с инструментами разработки desktop C++, для Linux — зависимости настольной сборки Flutter. Проверьте окружение через `flutter doctor`.
2. Откройте **Tools → Settings** и найдите раздел **Flutter SDK**.
3. Укажите абсолютный путь к корню SDK, например `/opt/flutter` или `C:\src\flutter`. Выбирайте папку, содержащую `bin/flutter` или `bin/flutter.bat`, а не сам исполняемый файл. Кнопка **Browse SDK** открывает выбор папки.
4. Нажмите **Test Flutter**. Tamtoot выполняет `flutter --version --machine`, показывает версии Flutter и Dart, затем запрашивает доступные устройства командой `flutter devices --machine`. Ошибки отображаются в настройках и Output. Проверка не собирает приложение и не гарантирует исправность всей цепочки сборки; для этого используйте `flutter doctor` и пробный запуск проекта.
5. В **Device ID** можно выбрать обнаруженное устройство. Пустое поле означает текущий desktop (`windows`, `linux` или `macos`). В **Entry point** укажите путь относительно корня проекта; по умолчанию это `lib/main.dart`.

Эти настройки сохраняются автоматически для пользователя Tamtoot. Путь SDK не записывается в файлы проекта. На Windows SDK должен быть предварительно инициализирован: один раз выполните `flutter --version` в терминале, чтобы появились кэш Dart SDK и Flutter tools.

## Запуск и остановка

Откройте папку Flutter-проекта с `pubspec.yaml`. Обычный новый пустой проект Tamtoot ещё не является Flutter-проектом: создайте структуру через инструменты Flutter и откройте её корень.

- **Run Flutter** запускает приложение без остановок отладчика.
- **Debug Flutter** запускает приложение с подключённым отладчиком внутри Tamtoot.
- **Stop Flutter** завершает сессию и запрашивает остановку запущенного приложения.
- **Hot reload** обновляет код запущенного приложения с сохранением состояния.
- **Hot restart** перезапускает приложение с обновлённым кодом и сбрасывает его состояние.

Кнопки находятся на верхней панели и в меню **Run**. На macOS это системное меню. Перед запуском и горячим обновлением Tamtoot сохраняет изменённые документы; если сохранение отменено, команда не продолжается. Вывод сборки, сообщения приложения и ошибки находятся во вкладке **Output**. Одновременно поддерживается одна Flutter-сессия на окно Tamtoot.

## Точки остановки, стек и переменные

Откройте сохранённый локальный файл `.dart`, поставьте курсор на нужную строку и выберите **Run → Toggle breakpoint at cursor**. Повторная команда удаляет точку. Все точки видны в **View → Debug** и могут быть удалены кнопкой рядом с ними. Они действуют в текущем окне и пока не сохраняются между перезапусками Tamtoot. SDK может отклонить точку или привязать её к другой исполняемой строке; сообщения о неподтверждённых точках выводятся в Output.

Во вкладке Debug доступны **Pause**, **Continue**, **Step over**, **Step into** и **Step out**. Когда приложение остановлено, Tamtoot показывает стек вызовов и переменные выбранного кадра. Нажатие на кадр открывает его исходный файл и переводит курсор на соответствующую строку. Объекты в списке переменных раскрываются по запросу. Без остановки приложения стек и переменные очищаются.

Это отладка Dart-кода Flutter. Отладка нативного C++/Swift-кода, условные точки, watch-выражения, attach к уже запущенному приложению и Flutter Inspector в этой реализации не добавлены.

## Особенность macOS

Текущие entitlements Tamtoot включают **App Sandbox**. Она может блокировать выполнение внешнего Flutter SDK, запись его кэша и доступ инструментов сборки к проекту. Настройки и команды реализованы, но полноценный запуск SDK из такой сборки не гарантирован. Для работы со сторонним SDK нужна отдельная настольная сборка с подходящими правами; отключение App Sandbox пока не применено и требует отдельного согласования. Такое изменение также влияет на возможность распространять приложение через Mac App Store.

## Как устроено подключение

Tamtoot запускает `flutter debug-adapter` и обменивается сообщениями Debug Adapter Protocol через стандартные потоки процесса. Запуск, точки остановки, шаги, стек и переменные реализованы общим клиентом; слой запуска процесса различается только по ОС. На Windows инструменты Flutter запускаются через кэшированный `dart.exe` и `flutter_tools.snapshot`, чтобы пути SDK не проходили через командную оболочку.

Описание протоколов: [Flutter Debug Adapter Protocol](https://github.com/flutter/flutter/blob/main/packages/flutter_tools/lib/src/debug_adapters/README.md), [DAP specification](https://microsoft.github.io/debug-adapter-protocol/specification).
