# Файлы проекта и платформы

[← Оглавление](README.md)

## Каталог `.tamtoot`

Tamtoot использует проектный каталог для настроек IDE, запросов, кеша и локальных инструментов:

```text
.tamtoot/
├── agents/
│   ├── instructions.md
│   ├── kanban.json
│   └── models/
│       └── <profile-id>.json
├── cache/
│   └── completions-v2.json
├── hooks/
│   └── <HookType>
├── requests/
├── worktrees/
├── environment.json
├── environment.local.json
└── mcp.json
```

Встроенная Git-панель исключает большую часть `.tamtoot`, чтобы профили моделей, промты, MCP-заголовки, Kanban, хуки, кеш и worktree оставались локальными. Исключение сделано для командных HTTP-запросов и `.tamtoot/environment.json`: они видны в Git и могут передаваться другим разработчикам.

Другой Git-клиент может добавить локальные файлы, если они не перечислены в `.gitignore`. Перед коммитом через сторонний клиент проверяйте содержимое `.tamtoot`, особенно `mcp.json`, профили и локальные окружения.

## Поддержка платформ

| Возможность | Desktop | Android | iOS | Web |
| --- | --- | --- | --- | --- |
| Редактор и подсветка | Да | Да | Да | Да |
| Локальные файлы и папки | Да | Через системный выбор | Экспорт пока ограничен | Зависит от API и разрешений браузера |
| HTTP-запросы к моделям | Да | Зависит от сети | Зависит от сети | Требуется CORS |
| Команды и исполняемые хуки | Да | Нет процесса ОС | Нет процесса ОС | Нет |
| STDIO MCP | Да | Нет | Нет | Нет |
| HTTP MCP | Да | Зависит от сети | Зависит от сети | Требуется CORS |
| Git worktree | Да | Нет | Нет | Нет |
| Flutter SDK и Dart-отладка | Да | Нет | Нет | Нет |

На macOS после выбора папки через системный диалог Tamtoot сохраняет
security-scoped bookmark, чтобы проект открывался снова после перезапуска.
Если доступ всё же отозван (переустановка приложения, сброс разрешений),
откройте **File → Open project… → Choose folder…** и выберите каталог заново.

На Windows, Linux и macOS команда **File → Add folder to workspace…** добавляет
в Solution второй и последующие корни, не закрывая основной проект. Корни
разворачиваются независимо, сохраняются в сессии и доступны встроенному агенту.
Основным для Git, Flutter, Requests и настроек `.tamtoot` остаётся первый корень;
дополнительную папку можно убрать крестиком рядом с её названием.

## Безопасность данных

- API-ключ модели хранится только в памяти окна запуска.
- HTTPS обязателен для публичных endpoint моделей и MCP. HTTP разрешён для localhost и, где указано, приватной сети.
- `.tamtoot/environment.local.json` предназначен для секретов HTTP-запросов.
- Заголовки MCP сохраняются буквально, поэтому используйте короткоживущие токены.
- YOLO требует чистое Git-дерево и сохраняет ограничения команд и путей.
- Встроенный агент не является системной песочницей: он уменьшает риск ошибочных действий, но не заменяет изоляцию ОС.

## Текущие ограничения

Полный LSP, отладка нативного кода, PTY-терминал, хостинг исполняемых расширений, сложный docking и отдельные группы редактора находятся в планах. Git-клиент пока ограничен для packed/shallow историй, сложного staging, конфликтов слияния, submodule и некоторых схем репозитория.

## Создание нового проекта

**File → New project…** создаёт пустую папку проекта и открывает её в IDE. Укажите имя проекта. На Windows, Linux и macOS выберите родительскую папку на диске: внутри неё появится отдельная директория с именем проекта. Клонирование репозитория на этих платформах также требует выбора родительской папки и сохраняет файлы непосредственно на диске.

На Android и iOS новые и клонированные проекты сохраняются во внутреннем хранилище приложения `TamtootRepos`. Новый проект не перезаписывает существующую папку; при совпадении имени выберите другое. Маркер `.tamtoot/project.json` позволяет находить созданные проекты через **File → Open project…**, даже если в них ещё нет файлов и Git-репозитория. Git-репозиторий и шаблон языка при создании пустого проекта автоматически не добавляются.

Настольный запуск и отладка Dart-кода Flutter описаны отдельно: [Flutter SDK, запуск и отладка](flutter-run-and-debug.md).
