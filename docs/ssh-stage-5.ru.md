# SSH: этап 5 — SFTP и завершение основного сценария

Реализован основной набор этапов 1–5: профили и ключи → защищённое соединение и доверие серверу → вход и команды → интерактивный терминал → SFTP. Дополнительные возможности этапа 6 (туннели, новые форматы ключей, отдельный менеджер нескольких сессий) остаются расширениями первого выпуска.

## Использование

В Settings → SSH создайте профиль, нажмите Connect, проверьте ключ сервера и войдите. После входа доступны **Open terminal** и **Open SFTP**, а также выполнение отдельных команд.

SFTP открывает пользовательский каталог сервера. Поле Remote path позволяет перейти по удалённому пути, Parent — подняться выше. Папки открываются нажатием; для ссылок показывается подтверждение и цель ссылки. Upload загружает локальный файл, New folder создаёт папку. Меню файла содержит Download, Edit text, Rename и Delete. Переименование и удаление требуют подтверждения; каталоги удаляются только пустыми. Удаление ссылки сохраняет её цель.

Редактор принимает UTF-8-текст до 2 МиБ. Save remote проверяет исходную версию, Reload remote file позволяет перечитать серверную версию с подтверждением потери локальных правок. Уход с несохранёнными изменениями требует подтверждения. Редактор не сохраняет удалённый документ в историю агента, проект или настройки.

## Протокол и пределы

- Используется собственный SFTP v3 на Dart через SSH `subsystem=sftp`. Приложение не запускает системный SFTP, SSH или shell для передачи файлов.
- Согласуются версия 3 и до 32 расширений. Неизвестные расширения сохраняются как объявления сервера и не включаются автоматически. Если сервер объявляет `fsync@openssh.com=1`, записанный временный файл сбрасывается перед закрытием.
- Максимум восемь одновременно ожидающих запросов. Ответы связываются по ID и могут приходить в ином порядке. Передача одного файла выполняется последовательными блоками по 32 КиБ; конкурентная передача файлов в одном SFTP-клиенте запрещена.
- Пакет SFTP ограничен 256 КиБ. Частичные заголовки и тела собираются между SSH-пакетами; неизвестный ID, неверная версия или повреждённый ответ завершают SFTP и отклоняют все ожидающие запросы.
- Запросы и ожидание следующего блока источника имеют тайм-аут 30 секунд. Прогресс учитывает подтверждённые блоки; отмена закрывает SFTP-канал и отклоняет ожидания, включая остановившийся источник. Завершение старой операции делает её обработчик отмены неактивным: поздняя отмена не закрывает следующую сессию.
- В интерфейсе бинарный файл ограничен 32 МиБ и буферизуется в памяти. Каталог — 10000 записей, 4096 записей на страницу и 1024 страницы. Пути/имена должны быть корректным UTF-8; POSIX-разделитель `/` не смешивается с локальным путём. Обратная косая черта допустима в имени на удалённой стороне.
- Есть realpath, lstat/stat, readlink, каталог, открытие/чтение/запись/закрытие, mkdir, remove/rmdir и rename. Приватные ключи и пароли не участвуют в SFTP-запросах после входа.

## Сохранение и восстановление

Загрузка всегда сначала создаёт случайно названный `.tamtoot-upload-…` **в том же удалённом каталоге**, с exclusive create. Новый файл создаётся с правами 0600. При замене сохраняются обычные биты rwx; владелец/группа нового файла определяются сервером, setuid/setgid и ACL не переносятся автоматически.

Для замены существующего файла:

1. Пользователь подтверждает замену либо сохраняет документ, открытый в редакторе. Из исходной версии запоминаются байты, размер, mtime и права. Символические ссылки не заменяются и не редактируются автоматически.
2. Перед записью и перед завершением сверяются атрибуты и всё содержимое. Это обнаруживает изменение даже при совпавших размере и времени.
3. Прежний файл переименовывается в случайный `.tamtoot-backup-…`. Его содержимое проверяется ещё раз после переноса, чтобы обнаружить изменение между предварительной проверкой и переименованием.
4. Временный файл переименовывается на место назначения обычным SFTP v3 rename, который не должен перезаписывать появившийся чужой файл. Резервная копия сохраняется и её путь показывается пользователю.
5. При отказе новая запись удаляется, если соединение доступно; прежняя версия восстанавливается, если её место свободно. Если восстановлению мешает другой файл или обрыв, выводится путь восстановления. Чужой файл не удаляется автоматически.

Это **не атомарная замена существующего файла**: между переносом прежней версии и установкой новой возможен временный промежуток без пути назначения. Наличие `posix-rename@openssh.com` не означает compare-and-swap; расширение намеренно не используется для безусловной перезаписи. Серверный протокол v3 не позволяет гарантировать транзакционность против любых внешних писателей. Резервная копия остаётся доступной также писателям, которые держали старый inode открытым.

Для нового пути применяется одна операция rename; поведение/атомарность определяется сервером и его файловой системой. fsync файла не является гарантией fsync каталога или сохранности при любом сбое сервера. При разрыве после запроса фиксации результат может быть неопределённым: ошибка не выдаётся за успешную передачу, состояние нужно перечитать. После отмены/разрыва на сервере может остаться временный файл; его имя начинается с `.tamtoot-upload-`. Случайные оставшиеся файлы других операций автоматически не удаляются.

Скачивание завершается только после EOF, закрытия handle и проверки атрибутов; изменения размеров/mtime считаются конфликтом. Экспорт в локальное хранилище начинается после полного успешного скачивания. Ошибка или отмена диалога сохранения не выдаётся за сохранённый локальный файл.

## Платформенные диалоги

Desktop использует уже существующий в проекте системный file-selector adapter. При локальном сохранении данные сначала записываются во временный файл рядом с выбранным назначением и затем переименовываются.

Android — собственный Kotlin-адаптер ACTION_OPEN_DOCUMENT/ACTION_CREATE_DOCUMENT, чтение/запись байтов через ContentResolver. iOS — собственный Swift-адаптер UIDocumentPicker, security-scoped чтение с NSFileCoordinator и экспорт временного файла. Чтение на мобильных платформах ограничено 32 МиБ во время обработки потока, а не только предварительным размером. Широкие права на хранилище не запрашиваются; новых библиотек не добавлено.

При уходе Android/iOS в paused открытый SFTP-сеанс явно отключается. Системный диалог выбора/сохранения файла является исключением: соединение не закрывается самим интерфейсом, но всё равно может быть прервано ОС. Автоматического переподключения и повторного выполнения файловых операций нет. Закрытие страницы закрывает только SFTP-канал, оставляя основное SSH-соединение доступным.

## Проверка и границы выпуска

- Реальный изолированный OpenSSH: версия/расширения, realpath, каталог/атрибуты, бинарный Unicode-файл 170000 байт с rekey, редактирование и резервная копия, конфликт, symlink/readlink, rename, удаление, отмена и выполнение команды при открытом SFTP-канале.
- Моделируемый сервер: побайтовая фрагментация, ответы вне порядка, восемь ожидающих ID, неверные версия/размер/ID, конфликт при одинаковых размере/mtime, гонка rename, сохранение конкурирующего назначения, отмена зависшего источника и поздняя отмена уже завершённой передачи.
- Виджеты: ширина 430 px, бинарный экспорт/импорт, подтверждение удаления, редактор, конфликт, подтверждённый Reload и сохранение recovery copy.
- Общий набор проверяет также этапы 1–4. Итоговые числа и сборки записаны в [verification.md](verification.md).

Windows/Linux-сборки, физические устройства, системные providers/IME на них и независимый аудит собственной криптографии ещё требуют отдельной проверки. Это не заявление о полной совместимости со всеми SSH/SFTP-серверами или готовности к использованию с важными серверами без аудита. Web-сборка не является прямым SSH-клиентом по условиям исходного плана.

Код: `lib/core/sftp/sftp_client.dart`, `lib/features/sftp_browser_view.dart`, `lib/platform/sftp_files*.dart`, `android/.../SftpFiles.kt`, iOS `SftpDocumentBridge` в AppDelegate.

Спецификации: [SFTP v3 — draft-ietf-secsh-filexfer-02](https://www.ietf.org/archive/id/draft-ietf-secsh-filexfer-02.txt), [расширения OpenSSH](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL).
